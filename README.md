# tg-digest

Дайджест и Q&A по закрытой Telegram-группе.

Три процесса над одной базой (PostgreSQL + pgvector). По умолчанию они работают
в одном контейнере под супервизором (`APP_ROLE=all`), но могут жить и по отдельности:

| Процесс | Что делает | `APP_ROLE` |
|---|---|---|
| **collector** | Telethon от лица пользователя: читает группу, пишет сообщения, расшифровывает голосовые | `collector` |
| **bot** | aiogram: дайджест, `/ask` по истории, поиск, рейтинги, бот-копировщик | `bot` |
| **web** | FastAPI: админка, только для владельца | `web` |

Bot API не может читать историю закрытой группы и качать защищённое медиа — это
умеет только пользовательский аккаунт через MTProto. Поэтому процессов два, а бот
служит интерфейсом.

Полное техзадание — [`docs/TZ.md`](docs/TZ.md).
Состояние работ — [`docs/PROGRESS.md`](docs/PROGRESS.md).
Как завести `.env` и где взять ключи — [`docs/SETUP.md`](docs/SETUP.md).

## Быстрый старт локально

```bash
make install-dev
cp .env.example .env     # заполнить по docs/SETUP.md
make login               # первый вход в Telegram, напечатает TG_SESSION_STRING
make migrate             # создать таблицы
make run-all             # всё сразу, как на сервере
# или по отдельности:
make run-collector       # сбор сообщений
make run-bot             # бот в личке
make run-web             # админка
```

Проверки: `make check` (ruff + mypy + тесты).
Для интеграционных тестов нужен Postgres с pgvector — поднимается через
`./scripts/test_db.sh start`.

## Деплой на Amvera

По умолчанию всё работает **одним приложением** (`APP_ROLE=all`): внутри контейнера
маленький супервизор (`src/supervisor.py`) накатывает схему БД, запускает bot, web и
collector отдельными процессами и перезапускает упавший, не трогая остальные.
Одни переменные, один деплой, один адрес. Памяти нужно около 300–400 МБ, если
голосовые расшифровывает Telegram (`ASR_PROVIDER=telegram`), а не локальный whisper.

Разнести процессы по трём проектам по-прежнему можно: в каждом задать свою
`APP_ROLE` (`bot`, `web`, `collector`) — образ и `amvera.yml` общие.

### Что сделать руками до деплоя

1. **Сгенерировать строку сессии на своей машине.** На Amvera код из Telegram
   ввести некуда:
   ```bash
   make login
   ```
   Скрипт напечатает `TG_SESSION_STRING` и список групп с их id.
   **Строка равнозначна паролю от аккаунта** — только в секреты Amvera,
   никогда в код, в логи или в переписку.

2. **База.** Supabase → Connect → **Session pooler** (порт 5432) — это
   `DATABASE_URL`. Схему накатит само приложение при старте. Пулер в этом режиме
   пускает до 15 подключений на всю базу, поэтому супервизор даёт каждому из трёх
   процессов пул на 4 соединения (`DB_POOL_SIZE`, если задан, главнее).

3. **Создать один проект** на Amvera из этого репозитория.

4. **В @BotFather** выполнить `/setdomain` для бота и указать адрес приложения —
   иначе кнопка «Войти через Telegram» в админке не заработает.

### Переменные окружения

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | строка Session pooler из Supabase (секрет) |
| `OWNER_ID` | твой Telegram id |
| `TG_GROUP_ID` | id основной группы — при первом старте она сразу включена |
| `TG_API_ID`, `TG_API_HASH` | с my.telegram.org |
| `TG_SESSION_STRING` | из `make login` (секрет) |
| `BOT_TOKEN` | токен бота (секрет) |
| `BOT_USERNAME` | имя бота без `@` — для виджета входа |
| `WEB_SECRET_KEY` | любая длинная случайная строка (секрет) |
| `WEB_BASE_URL` | адрес приложения на Amvera |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | DeepSeek; `LLM_THINKING=disabled` |
| `ASR_PROVIDER` | `telegram` — голосовые расшифровывает Telegram Premium |

Необязательные: `TZ` (по умолчанию `Europe/Moscow`), `BACKFILL_DAYS` (по умолчанию 7),
`TELEGRAPH_TOKEN`, `PROXY_URL`, `SERVICES` (по умолчанию `bot,web,collector`).
`APP_ROLE` задавать не нужно — по умолчанию `all`.

Если какой-то части не хватает переменных, супервизор её не запускает и пишет в
лог, чего не хватает, — остальные части работают. Например, без
`TG_SESSION_STRING` поднимутся бот и админка, а коллектор — после того, как
строку добавят и перезапустят приложение.

### Что происходит при первом запуске

1. Накатывается схема БД.
2. Группа из `TG_GROUP_ID` заводится включённой: сбор, дайджест, копировщик.
   Публикация дайджеста в саму группу при этом **выключена** — её включает
   владелец в админке (см. ниже). Остальные группы появляются выключенными.
3. Коллектор сам заливает историю за `BACKFILL_DAYS` дней (по умолчанию 7) и
   дальше только дописывает новое. Прогресс хранится в БД: рестарт посреди
   заливки продолжит с того же места. Залить больше позже — `BACKFILL_DAYS=30` и
   `python -m src.collector.backfill --days 30 --restart`; `BACKFILL_DAYS=0` —
   не заливать историю вовсе.

### Что проверить сразу после деплоя

| Проверка | Как |
|---|---|
| Все части запустились | в логах `Запускаю: bot, web, collector`; если какой-то нет — строка `… не запущен: не заданы …` |
| Коллектор подключился к Telegram | в логах `Вошли как …`; «Сессия Telegram недействительна» — перегенерировать `TG_SESSION_STRING`; нет подключения вовсе — MTProto не проходит, см. ниже |
| История залилась | в логах `Заливка истории за 7 дн.: …` |
| Схема накатилась | `/system` в админке, отметка `schema_applied_at` |
| Сообщения идут | `/stats` в личке бота, растёт счётчик |
| Голосовые расшифровываются | `/stats`, поле «расшифровано» |
| Админка закрыта | открыть её в режиме инкогнито — должно перекинуть на `/login` |
| Дайджест приходит | в 23:30 по `TZ`, либо `/digest` вручную |

### Публикация дайджеста в группу

По умолчанию дайджест видит только владелец: в личке и в админке («Дайджесты» —
архив по дням, внутри — как его увидит группа). На странице «Группы» у каждой
группы есть режим «Дайджест в группу»:

- **только мне** — ничего в группу не уходит (по умолчанию);
- **по кнопке** — после вечерней сборки бот присылает владельцу кнопку
  «📢 Опубликовать в группе» (с подтверждением); та же кнопка есть в админке;
- **автоматически** — дайджест каждый вечер сам уходит в группу без звука,
  владельцу приходит ссылка на пост.

Дайджест группы публикуется только в неё же, без кнопок оценки; строка «Герои
дня» с именами — только если в группе включён «Рейтинг недели». Опубликованный
по ошибке пост можно убрать кнопкой «убрать из группы» в течение 48 часов.
Для проверок без живого Telegram бота можно направить на подставной Bot API:
`BOT_API_URL=http://127.0.0.1:…`.

### Ограничения, которые важно соблюдать

- **Коллектор строго в одном экземпляре.** Две копии с одной сессией дают
  `AUTH_KEY_DUPLICATED`, и Telegram может сбросить авторизацию. Никаких реплик
  у проекта; при обновлении — сначала остановить, потом запустить.
- **MTProto может не пройти.** Amvera заявляет иностранный IP для HTTP API, а
  Telethon ходит по MTProto к дата-центрам Telegram. Если коллектор не
  подключается — задать `PROXY_URL=socks5://user:pass@host:port`.
- **Память.** Без локальных моделей все три процесса занимают около 300–400 МБ.
  `faster-whisper small` добавляет около 1.6 ГБ, `bge-m3` — ещё около 2 ГБ, поэтому
  в образе нет `sentence-transformers`. Без эмбеддингов поиск и `/ask` работают
  по словам; поиск по смыслу включается через API (`EMBED_BACKEND=api`,
  `EMBED_BASE_URL`, `EMBED_API_KEY`). С `ASR_PROVIDER=telegram` whisper не нужен.
- **Бэкапы.** Включить бэкапы PostgreSQL и `/data` в настройках Amvera:
  в `/data` лежат сессия Telegram, скачанные голосовые и кэш моделей.

### Локальный запуск образа

```bash
docker build -t tgdigest .
docker run --rm --env-file .env -p 8080:80 -v $PWD/data:/data tgdigest   # всё сразу
docker run --rm -e APP_ROLE=bot --env-file .env -v $PWD/data:/data tgdigest   # только бот
```

Для локальных эмбеддингов образ собирается с дополнительным набором:
```bash
docker build --build-arg EXTRAS=media,web,ml,embed -t tgdigest .
```

## Приватность

Содержимое групп не публикуется и не пересылается никуда, кроме личных сообщений
владельца. Единственное исключение — дайджест группы в эту же группу, и только если
владелец сам включил публикацию для неё в админке (по умолчанию выключено). Бот отвечает только владельцу (кроме публичного копировщика в
разрешённых группах). В админке нет ни одной страницы без авторизации.
Таблицы в Supabase закрыты RLS — подробности в `docs/PROGRESS.md`.
