## 0. Что строим

Система из двух процессов, работающих с одной БД:

1. **Collector (userbot, Telethon)** — сидит в закрытой группе от лица моего аккаунта, пишет каждое сообщение в базу, скачивает и расшифровывает голосовые, снимает подписи с картинок.
2. **Bot (aiogram, Bot API)** — интерфейс в личке: получает дайджест раз в сутки, отвечает на вопросы по истории чата (RAG), ищет сообщения. Сюда же переезжает мой существующий бот-копировщик.

Почему два процесса, а не один: **Bot API физически не может** читать историю закрытой группы и качать защищённое медиа. Читать может только user-аккаунт через MTProto. Бот — это только UI.

### Про ограничение «запрещено копирование и скачивание»

Флаг группы `noforwards` / «Ограничить сохранение контента» — это **клиентское** ограничение (прячет кнопки в официальных приложениях). MTProto-клиент, авторизованный как участник группы, получает и текст, и файлы штатно. Telethon работает.

Практические выводы, которые надо заложить в проект:
- Данные хранятся **только локально / на своём VPS**. Никакой публичной выдачи, никаких пересылок дайджеста в другие чаты — только мне в личку.
- Хранить `.session` файл с правами `600`, никогда не коммитить.
- Использовать основной аккаунт (он уже в группе), но с адекватными лимитами: не флудить API, ловить `FloodWaitError`, не делать массовых `iter_messages` без пауз.
- Бэкфилл истории делать один раз, порциями по 200 сообщений с паузой 1–2 сек.

### Нюансы по моделям (заложить в адаптер, не хардкодить)

- **GLM-5.3-Flash** — дёшево, мультимодально (можно кидать картинки прямо на анализ), но **reasoning отключить нельзя**. Для дайджеста ставить `reasoning_effort: "low"`, иначе на каждом вызове улетают десятки тысяч output-токенов. Base URL: `https://api.z.ai/api/paas/v4` или `https://open.bigmodel.cn/api/paas/v4`.
- **DeepSeek** — официальные имена моделей проверить в их docs на момент сборки (исторически `deepseek-chat` / `deepseek-reasoner`; у шлюзов-реселлеров имена свои). Адаптер должен принимать произвольное `MODEL_NAME`.
- Для регистрации без китайского номера — либо OpenRouter, либо шлюз-агрегатор. Всё OpenAI-совместимое, поэтому меняется только `base_url` + `model`.

## 4. Функционал по модулям

### 4.1 Collector

- Старт: логин по `.session`, если нет — интерактивно (код приходит в Telegram, потом 2FA-пароль).
- `events.NewMessage(chats=[GROUP_ID])` → нормализация → вставка в `messages` (upsert по `chat_id + tg_msg_id`).
- `events.MessageEdited` → обновить текст, проставить `edited_at`.
- `events.MessageDeleted` → мягкое удаление (флаг, не DELETE — дайджест за день должен остаться честным).
- Медиа:
  - `voice`/`audio`/`video_note` → скачать → faster-whisper → `transcript`;
  - `photo` → скачать → (опц.) мультимодальная модель, короткое описание в `transcript`;
  - остальное — только метаданные.
- Резолв авторов: кэш `tg_user_id → имя`, обновлять раз в сутки.
- Отказоустойчивость: при рестарте дочитать пропущенное от `state.last_msg_id` через `iter_messages(min_id=...)`.
- Все сетевые вызовы — через опциональный SOCKS5-прокси из `.env`.

### 4.2 Сегментация на треды (`nlp/threads.py`)

Правила, по порядку:
1. Если есть `topic_id` (форумная группа) — это базовая группировка.
2. Reply-цепочки склеиваются в один тред транзитивно.
3. Сообщения без reply приклеиваются к последнему активному треду, если прошло **< 25 минут** и пересекаются участники.
4. Иначе — новый тред.
5. Треды короче 3 сообщений и без вопросительных знаков — помечаются `low_value`, в дайджест идут только строкой «прочее».

### 4.3 Дайджест (map-reduce)

Cron `30 23 * * *` по Asia/Kamchatka.

1. Выбрать сообщения за сутки (00:00–23:59 локальных).
2. Отфильтровать шум: стикеры, реакции-репликами («+», «ок», «спасибо», ≤2 слов) — из map-стадии убрать, но в статистике учесть.
3. **Map**: по каждому треду → JSON `{тема, о чём спорили, что решили, открытые вопросы, ссылки, упомянутые инструменты/цены/имена, msg_ids ключевых сообщений, contributors: [{tg_user_id, role: initiator|key|answerer}]}`. `contributors` пишется в `thread_contrib` (для рейтингов, 4.10).
4. **Reduce**: отбор и ранжирование тем — по скорингу из раздела 4.7 (не «по числу сообщений»).
5. Рендер Markdown:
   - `📌 Главное за день` — 3 буллета;
   - по каждой теме: заголовок, 2–4 предложения, кто участвовал, **дип-линк** на стартовое сообщение;
   - `❓ Без ответа` — вопросы, на которые никто не ответил;
   - `🔗 Ссылки дня`;
   - `📊` — N сообщений, M участников, самый активный тред.
6. Дип-линк для супергруппы: `https://t.me/c/{abs(chat_tg_id) - 1000000000000}/{tg_msg_id}`.
7. Отправить в личку, сохранить в `digests`.
8. Идемпотентность: повторный запуск за тот же день перезаписывает запись, а не дублирует сообщение.

### 4.4 Q&A (RAG)

- Чанкование: по тредам; если тред длинный — окна по ~800 токенов с перехлёстом 100.
- Индексация: инкрементально, раз в час, только новые треды.
- Поиск: **гибрид** — pgvector cosine top-30 + FTS `russian` top-30 → слияние Reciprocal Rank Fusion → top-8.
- Расширение контекста: к каждому найденному чанку добавить ±3 соседних сообщения треда.
- Ответ: модель получает системный промпт «отвечай только по контексту чата, если нет данных — так и скажи», выдаёт ответ + список источников (дата, автор, дип-линк).
- Всё логируется в `qa_log`.

### 4.6 Интеграция с ботом-копировщиком

Исходник: aiogram 3, реагирует на @упоминание в группе, кладёт текст на Telegraph, отвечает кнопкой-ссылкой. Переписанная версия — `src/bot/handlers_copier.py` (готовый файл приложен, Claude Code его не пишет с нуля, а встраивает).

Решения:
- **Один бот.** Токен — от существующего копировщика: он уже состоит в группе. Токен только из `.env`.
- **Доступ.** Роутер копировщика публичный (как сейчас, работает для всех в группе). Роутеры Q&A — только OWNER_ID в личке. Порядок подключения: `copier` → `qa`. Catch-all «любой текст → /ask» только при `F.chat.type == "private"` и `F.from_user.id == OWNER_ID`.
- **/start** обрабатывает основной бот (в тексте помощи — описание копировщика); в копировщике своего /start нет.
- **Два режима вызова:** `@bot текст` → копирует текст после упоминания (как было); `@bot` реплаем на сообщение → копирует то сообщение (новое).
- **Связь с БД:** если сообщение из `TG_GROUP_ID` → `repo.mark_copied(chat_tg_id, tg_msg_id, text, tg_user_id, author_name, date)`: upsert; если запись есть (её уже сохранил collector) — `is_pinned_by_me = true`, `copy_count += 1`, `source` не менять; если нет — вставить с `source='copier'`. Ошибка БД не ломает копирование.
- **Кнопка «🧵 Что обсуждали вокруг»** — callback, только для OWNER_ID, ответ приходит в личку, в группу ничего не пишется.
- **`answer_about_thread(chat_tg_id, tg_msg_id) -> str`** в `src/rag/answer.py`: найти тред сообщения, взять до ±20 сообщений, вернуть краткое резюме в HTML (разрешённые Telegram-теги) с дип-линками на ключевые реплики.

Исправлено относительно исходника:
- `bot.get_me()` вызывался на каждое сообщение → кэш при старте;
- синхронный `telegraph` блокировал event loop → `asyncio.to_thread`;
- срез по `entity.offset` ломался, если до упоминания был эмодзи (Telegram считает offset в UTF-16) → `entity.extract_from`;
- новый аккаунт Telegraph при каждом рестарте → токен сохраняется в `.env`;
- токен бота в коде → `.env`.

Известный риск: страница Telegraph открывается любым, у кого есть ссылка, — контент закрытой группы уходит на внешний сервис. Оставлено как в исходнике; на будущее — режим `COPY_MODE=dm` (текст присылается запросившему в личку, если он запускал бота).

### 4.7 Отбор важного (заменяет простой reduce из 4.3)

Модель не дообучается. «Ум» системы — это скоринг из трёх слоёв плюс обратная связь, которая подстраивает веса и примеры. Всё хранится в `digest_items.features`, поэтому любое решение можно разобрать в админке: почему тема попала или не попала.

**Слой 1. Сигналы вовлечённости (без LLM, бесплатно).** Считаются по каждому треду:
- `participants` — уникальные авторы;
- `replies` — длина reply-цепочек, глубина;
- `reactions` — сумма реакций (из `message.reactions`);
- `duration_min` — сколько длилось обсуждение;
- `author_weight` — средний `authors.weight` участников (эксперты группы весят больше);
- `links`, `has_numbers` — наличие ссылок, цен, цифр, названий инструментов;
- `owner_signal` — я копировал, пинил или отвечал в треде;
- `answered` — был ли вопрос и получил ли он ответ.

Каждый сигнал нормализуется **относительно самой группы** (перцентиль за последние 30 дней), иначе в активной группе всё «популярно», а в тихой — ничего.

**Слой 2. LLM-оценка по рубрике (дешёвая модель, reasoning low).** Один вызов на тред, строго JSON:

```json
{
  "kind": "decision|insight|resource|announcement|question|drama|other",
  "usefulness": 0-10,      // можно ли это применить: совет, решение, рабочий способ
  "specificity": 0-10,     // конкретика: цифры, названия, шаги vs общие слова
  "relevance": 0-10,       // совпадение с профилем интересов группы
  "takeaway": "один вывод в одно предложение, без пересказа",
  "why": "почему это важно — одно предложение"
}
```

В промпт передаются: профиль интересов группы (редактируется в админке, например «интересно: AI-видео, Seedance, заказы, конкурсы; неинтересно: политика, флуд, самопиар»), **до 8 примеров из обратной связи** (4 последних 👍 и 4 последних 👎 с заголовками и takeaway), и явный запрет: «Не пересказывай. Оценивай, что читатель может вынести и применить».

**Слой 3. Новизна.** Эмбеддинг `title + takeaway` сравнивается с темами последних 7 дней. Косинус > 0.85 → `novelty` резко вниз, в дайджест идёт только если появилось что-то новое (LLM отдельно отвечает «что нового по сравнению с: …»).

**Итоговый скор:**
```
score = w_eng·engagement + w_use·usefulness + w_spec·specificity
      + w_rel·relevance + w_nov·novelty + w_own·owner_signal
```
Веса и порог — в `chats.settings`, правятся в админке. `kind=drama` и `muted`-авторы по умолчанию штрафуются. В дайджест идут темы выше порога, но не больше `top_n` (по умолчанию 6).

**Формат темы в дайджесте — не пересказ:**
```
🟢 [Решение] Seedance режет 15-сек ролики с 4K-референсами
Вывод: референсы >2K ужимать заранее, иначе обрезается хвост.
Почему важно: 3 человека независимо поймали, у Васи рабочий обход.
👥 5 · 💬 23 · ↗️ ссылка на ключевое сообщение
[👍] [👎] [🔕 не показывать такое]
```

**Обратная связь и обучение.**
- Кнопки 👍 👎 🔕 под каждой темой → `feedback`.
- Раз в неделю `jobs/retrain.py`: логистическая регрессия (scikit-learn) по `features` → `feedback.value`. Новые веса пишутся в `chats.settings.weights` как **предложение**; в админке видно «было / стало» и кнопка «применить». Минимум 30 оценок, иначе не трогать.
- «Показать отсеянное»: в админке и командой `/missed` — темы ниже порога за день. Если там было важное, 👍 на ней тоже учится.
- Результат: через 2–3 недели оценок система выбирает темы так, как выбрал бы я, а не по количеству сообщений.

### 4.8 Несколько групп и управление доступом

Одна база, все таблицы с `chat_id`. Для каждой группы свои настройки, профиль, веса и дайджест. Дайджесты разных групп приходят отдельными сообщениями, `/ask` по умолчанию ищет по всем, `/ask #имя_группы вопрос` — по одной.

**Collector (userbot):** читает **только** группы с `collect = true`. Новые группы, в которые вступает мой аккаунт, появляются в админке выключенными — включаю руками.

**Бот (копировщик):**
- обработчик `my_chat_member`: бота добавили в группу →
  - `copier = allow` → работает;
  - `deny` → сразу `leave_chat`;
  - `ask` (по умолчанию для новых) → мне в личку «Бота добавили в „X“, кто добавил: @user» с кнопками «Разрешить / Запретить и выйти»; до решения бот молчит;
- middleware перед роутером копировщика: чат не `allow` → игнор; автор в `copier_blocklist` → игнор;
- rate limit: не больше 10 копирований в минуту на пользователя.

**Команды владельца в личке:** `/groups` — список с переключателями, `/ban @user`, `/unban @user`. Всё то же самое есть в веб-админке.

### 4.9 Веб-админка

Стек: **FastAPI + Jinja2 + HTMX + Chart.js**, один сервис, без отдельной сборки фронта. Читает и пишет ту же БД. Bot и collector перечитывают настройки из БД раз в 60 секунд (или через `LISTEN/NOTIFY`), перезапуск не нужен.

**Авторизация:** Telegram Login Widget, пускать только `OWNER_ID` (проверка hash по токену бота). Домен админки прописать боту через @BotFather → `/setdomain`. Плюс сессионная кука, CSRF-токен на формы. Никаких публичных страниц: в админке содержимое закрытых групп.

**Страницы:**

| Страница | Что там |
|---|---|
| Дашборд | сообщений в день по группам, активные треды сейчас, расход токенов и $ за день/месяц, очередь расшифровки, ошибки за 24 ч, когда пришёл последний дайджест |
| Группы | все диалоги userbot'а и бота: collect / digest / copier (allow·deny·ask), время дайджеста, срок хранения, модель |
| Отбор | профиль интересов (текст), ползунки весов, порог, top_n; редактор промптов с версиями; **«Прогнать на вчера»** — превью дайджеста с новыми настройками рядом со старым, без отправки |
| Дайджесты | архив, по каждой теме — все `features` и почему она прошла/отсеялась; отсеянные темы с кнопкой 👍 |
| Обучение | число оценок, точность текущих весов на отложенных оценках, предложенные новые веса, «применить» |
| Участники | топ авторов по группе, `weight`, mute, блок в копировщике |
| Рейтинги | номинации за день/неделю/месяц/скользящие 7–30 дней, сортировка по любой метрике, профиль участника с трендом, скрыть из рейтингов, коэффициенты формулы |
| Q&A | лог вопросов и ответов, источники, кнопка «ответ плохой» |
| Система | статус процессов (heartbeat в `state`), ручной запуск дайджеста/бэкфилла/переиндексации, экспорт группы в JSON |

Все мутации пишутся в `settings` с `updated_at`, в админке видна история изменений.

### 4.10 Рейтинги участников

Периоды: **день / неделя / месяц** (неделя — пн–вс, месяц — календарный; плюс «скользящие 7 и 30 дней» в админке). Всё считается по группе отдельно.

**Сбор.** Job в 23:40 (после дайджеста, т.к. нужны его оценки тредов) пересчитывает `author_stats_daily` за день. Неделя и месяц — `sum()` по дням, отдельных таблиц не нужно. Пересчёт идемпотентный: можно перегнать любой день.

**Номинации:**

| Номинация | Метрика | Примечание |
|---|---|---|
| 🧠 Самый полезный | `usefulness` | главный рейтинг, формула ниже |
| 🛟 Помощник | `questions_answered` | закрыл чужие вопросы |
| 🔥 Заводила | `threads_started` | начал темы, попавшие в дайджест |
| 💬 Самый активный | `messages` | реплики ≤2 слов считаются как 0.3 |
| 📜 Писатель | `words` + `longest_msg` | многословность, с юмором |
| 🎯 Цепляет | `replies_got` / `messages` | на кого чаще отвечают, от 10 сообщений |
| ❤️ Любимец публики | `reactions_got` | |
| 🔗 Добытчик | `links` | |
| 🎙 Радиоведущий | `voice_sec` | минуты голосовых |
| 🦉 Сова | `night_msgs` | |

**Формула полезности** (за день):
```
usefulness = Σ по тредам дня: thread.score × вклад
             вклад: initiator 0.3 · key 0.5 · answerer 0.4 (роли суммируются, максимум 1.0)
           + 0.2 × перцентиль(reactions_got)
           + 0.3 × перцентиль(replies_got / messages)
```
`thread.score` берётся из скоринга 4.7, поэтому полезность автоматически учитывает твои 👍/👎: участник, чьи темы ты лайкаешь, растёт. Итог показывается как 0–100 (перцентиль внутри группы за период). Коэффициенты — в `chats.settings.ratings`, правятся в админке.

**Защита от накрутки.** Флуд (подряд >5 сообщений ≤3 слов за 2 мин) склеивается в одно. Реакции от одного человека одному автору — не больше 3 в день в зачёт. Самореплаи не считаются.

**Вывод:**
- `/top` — неделя, все номинации, топ-3 в каждой, стрелки ↑↓ к прошлому периоду;
- `/top day|week|month [#группа] [номинация]`, например `/top month полезный`;
- `/who <имя>` расширяется: место в каждой номинации за 30 дней, график активности;
- в ежедневный дайджест — строка «🏅 Герои дня: полезный · помощник · заводила»;
- автоотчёт по воскресеньям 23:45 (неделя) и 1-го числа (месяц) — мне в личку;
- админка, страница «Рейтинги»: таблица с сортировкой по любой метрике, переключатель периода, профиль участника, тренд по неделям, кнопка «скрыть из рейтингов».

**Публикация в группу** — выключена по умолчанию, флаг `chats.settings.ratings.publish`. По умолчанию рейтинги видишь только ты. Если включаю:
- публикуются только позитивные номинации (🧠 🛟 🔥 ❤️ 🔗 🎙 + шуточная 📜), без «самых бесполезных»;
- участники могут написать боту `/optout` → `hide_from_ratings = true`;
- в закрытой группе включать только с согласия её админов — бот-копировщик там по их разрешению, а рейтинг с именами — это уже новое поведение.

**Шаг 13. Деплой на Amvera.**

   ```python
   from telethon.sync import TelegramClient
   from telethon.sessions import StringSession
   with TelegramClient(StringSession(), API_ID, API_HASH) as c:
       print(c.session.save())
   ```

2. В Amvera создать managed PostgreSQL с расширением pgvector.
3. Создать три проекта из одного репозитория: `tgd-collector`, `tgd-bot`, `tgd-web`. Отличаются только командой запуска (переменная `APP_ROLE`).

> Подготовь деплой на Amvera: Dockerfile с APP_ROLE=collector|bot|web, amvera.yml, медиа и кэш моделей в /data (постоянное хранилище), миграции при старте bot. Collector читает TG_SESSION_STRING через StringSession. Добавь в README порядок деплоя и проверки.

Ограничения, которые надо учесть:
- **Collector строго в одном экземпляре.** Две запущенные копии с одной сессией → `AUTH_KEY_DUPLICATED`, Telegram может сбросить сессию. Никаких реплик, при деплое — сначала стоп, потом старт.
- **Проверить MTProto сразу после деплоя.** Amvera автоматически пускает трафик к Telegram через иностранный IP, но это заявлено для HTTP API; Telethon ходит по MTProto к дата-центрам Telegram. Если collector не подключается — `PROXY_URL` с SOCKS5.
- **Память.** faster-whisper `small` + bge-m3 вместе — около 3–4 ГБ ОЗУ. На Amvera это дорогой тариф, поэтому эмбеддинги через API (`EMBED_BACKEND=api`), whisper оставить в collector на тарифе от 2 ГБ, либо выключить расшифровку для групп, где голосовых мало.
- Бэкапы: включить бэкапы PostgreSQL и /data в настройках Amvera.

## 8. Стоимость (ориентир)

При ~500–1500 сообщений в день: map-reduce дайджест ≈ 150–400k входных токенов в сутки. На flash-моделях это единицы центов в день. Whisper и bge-m3 локально — бесплатно, нужен только CPU (VPS 2–4 vCPU / 4 ГБ).
