# CLAUDE.md

Полное техзадание — `docs/TZ.md`. Текущее состояние работ и что осталось — `docs/PROGRESS.md`.
Перед любой задачей: свериться с обоими файлами, после завершения этапа — обновить PROGRESS.

## Что это

Три процесса над одной БД (PostgreSQL + pgvector). На сервере они работают в одном
контейнере под супервизором (`src/supervisor.py`, `APP_ROLE=all` по умолчанию):
- **collector** (Telethon, user-сессия) — читает закрытую группу, пишет сообщения в БД,
  расшифровывает голосовые. Bot API этого не может физически.
- **bot** (aiogram 3) — интерфейс в личке владельца: дайджест, Q&A по истории, поиск,
  рейтинги. Сюда же встроен бот-копировщик.
- **web** (FastAPI) — админка, только для OWNER_ID; плюс страница участников `/g`
  (только чтение, по членству в группе, включает владелец).

## Правила разработки

- Python 3.11+, async везде, ruff + mypy.
- Никаких секретов в коде, только `.env` через pydantic-settings (`src/config.py`).
- SQL только в `src/db/repo.py`. Не писать в БД из хендлеров напрямую — только через repo.
- LLM-вызовы только через `src/llm/client.py`; модель и base_url — из `.env`, не хардкодить.
- Промпты — отдельными строками в `src/digest/prompts.py`, а не инлайном в логике.
- После каждого этапа: `make check` (lint + typecheck + test) + git commit.
- `.session`, `.env`, `data/` — в `.gitignore`, в репозитории секретов нет.

## Ограничение на боевые действия

**Ничего не писать в реальную группу и не отправлять сообщения от имени бота**,
пока владелец не разрешит явно. Это касается тестовых отправок, проверок «дойдёт ли
сообщение» и любых `send_message` в живой Telegram. Проверять всё на подставном
Telegram API и локальной базе: `BOT_API_URL=http://127.0.0.1:…` направляет бота
и админку на подставной Bot API.

Публикация дайджеста в группу (`src/digest/publish.py`) — функция продукта, а не
разрешение разработчику: по умолчанию выключена (`chats.publish = 'off'`), включает
её только владелец сам в админке. Не включать её за владельца и не проверять на живой
группе.

## Приватность (TZ §9)

- Содержимое групп не публиковать и не пересылать никуда, кроме личных сообщений владельца.
  Исключения по решению владельца: дайджест группы — в эту же группу, только если
  владелец включил для неё публикацию в админке; страница участников (`/g`,
  `src/web/portal.py`) — только чтение, только для тех, кто состоит в группе, и только
  если владелец открыл её для группы (`chats.portal`, по умолчанию `off`).
- Доступ к боту — только OWNER_ID (кроме публичного роутера копировщика в разрешённых группах).
- Ни одной страницы админки без авторизации владельца. Кука участника не должна открывать
  админку: `require_owner` сверяет uid с OWNER_ID на каждом запросе.
- На странице участников — только то, что увидела бы группа: без оценок тем, признаков,
  кнопок обучения, настроек и исходных сообщений; рейтинги — только `PUBLIC_NOMINATIONS`
  и без скрывшихся по /optout. Нельзя — отвечать 404, а не 403.
