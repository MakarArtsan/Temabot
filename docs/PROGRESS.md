## Сделано на шаге 2

- `src/db/schema.sql` — схема из TZ §3, **идемпотентная** (`if not exists` + именованные
  индексы), применяется при каждом старте без вреда данным.
- `src/db/pool.py` — пул asyncpg, кодек jsonb (в коде `dict`, не строка). SQL здесь не пишется.
- `src/db/models.py` — датаклассы строк + `Message.content` (текст и расшифровка равноправны).
- `src/db/repo.py` — единственное место с SQL: чаты, авторы, сообщения, state, дайджесты,
  учёт токенов.
- `src/db/migrate.py` + `make migrate` — применение схемы, отметка в `state.schema_applied_at`.
- 18 интеграционных тестов на настоящем Postgres 16 + pgvector 0.6. Без `TEST_DATABASE_URL`
  они skip, поэтому `make test` не падает на машине без базы.

**Решения, которых не было в ТЗ явно:**
1. Добавлена колонка `messages.deleted_at` — §4.1 требует мягкого удаления, а в схеме §3
   поля под него не было.
2. `upsert_message` не затирает поля, которые пишут другие процессы: `transcript`,
   `thread_id`, `is_pinned_by_me`, `copy_count`, `reactions`. Иначе бэкфилл поверх
   собранного стирал бы расшифровки и пометки копировщика.
3. Сутки считаются по локальной таймзоне (`Asia/Kamchatka`), а не по UTC — иначе дайджест
   за день режется на 12 часов раньше. Покрыто тестом.
4. `src/db/pool.py` — отдельный модуль (в §2 его нет). Правило «SQL только в repo.py»
   не нарушено: в пуле лежит только управление соединениями.
5. `chats.copier` ограничен `check (allow|deny|ask)`.

## Сделано на шаге 3

- `src/collector/client.py` — клиент Telethon: StringSession или файл сессии, разбор

- `src/collector/handlers.py` — чистая нормализация без сети и БД: тип медиа, сумма
  реакций, reply/topic для форумов, имя автора, кэш авторов с суточным TTL.
- `src/collector/service.py` — NewMessage / MessageEdited / MessageDeleted, докачка
  пропущенного при старте, heartbeat в `state`, режим `--dry-run`.
- `src/collector/login.py` (`make login`) — первый вход, печатает StringSession и список
  групп с id.
- `docs/SETUP.md` — как завести `.env`, где брать каждый ключ, как запускать.
- `scripts/test_db.sh` — локальный Postgres с pgvector для тестов.
- 35 тестов коллектора без живого Telegram (подделанные объекты сообщений).

**Решения, которых не было в ТЗ явно:**
1. Опорная точка докачки — `max(tg_msg_id)` из БД, а не `state.last_msg_id`. БД не
   разойдётся с реальностью, даже если процесс упал, не успев обновить state.
   `state` пишется для админки как heartbeat.
2. В форумной группе сообщение, отправленное в тему без ответа кому-либо, имеет
   `reply_to_msg_id` = корень темы. Считать это ответом нельзя — вся тема склеилась бы
   в одну reply-цепочку и сломала сегментацию (§4.2). Такое сообщение пишется с
   `reply_to = NULL`, `topic_id = корень`.
3. `video_note` (кружок) размечается как `voice` — расшифровывать его надо так же.
4. `raw` хранится компактным слепком (флаги forwarded/pinned/views), а не целиком:
   полный raw на сотнях тысяч сообщений раздувает базу.
5. Фильтр `collect = true` сделан сразу (это шаг 10), потому что иначе коллектор
   пришлось бы переписывать. При пустой таблице чатов первый запуск заводит группу
   из `TG_GROUP_ID` и включает сбор — иначе процесс стартует вхолостую.
6. Пустой текст нормализуется в `NULL`: иначе `coalesce` в upsert затирал бы
   осмысленный текст пустой строкой.
